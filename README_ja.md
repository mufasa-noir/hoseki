> Hoseki は、無料のWebチャットUI（Kimi、GLM、DeepSeek など）が、プロジェクトフォルダ内のファイルを読み取り・検索・編集し、あなたの承認のもとでコマンドを実行できるようにする**ローカルブリッジ**です。**LLM の API キーも有料プランも不要です。**

## 📜 はじめに

優れたモデルがブラウザのタブでは無料で使えても、ファイルを操作させようとした途端に有料の API キーが必要になることがよくあります。**Hoseki** はそのギャップを埋めます。チャットページとあなたのファイルシステムの間に入ることで、いま会話しているモデルが、ソフトウェア開発やセキュリティ観点のコードレビューを手伝えるようになります。

Hoseki は 3 つの小さな部品で構成されています。

1. **ローカルデーモン**: `127.0.0.1` 上の HTTP でファイル操作とコマンド実行のツールを公開します。パスジェイル、トークン認証、人間による承認ゲートを備えています。
2. **ブラウザ拡張機能**（Chrome 向けは Manifest V3、Firefox 向けは別ビルド）: チャットページを監視し、モデルの返信に含まれるツール呼び出しブロックを検出してデーモンへ送り、結果をチャットの入力欄に戻します。
3. **プロンプトのプリアンブル**: チャットの最初に貼り付けて、モデルにツール呼び出しプロトコルを教えるための文章です。

> **ステータス:** ロードマップの 6 つのフェーズはすべて実装済みです（[ロードマップ](#️-ロードマップ)を参照）。ただし Hoseki はまだ初期段階のソフトウェアで、特にサイトアダプターはベストエフォートです。チャット UI は予告なく変わるため、ときどきセレクターを更新する必要があります（[セレクターの探し方と設定方法](#セレクターの探し方と設定方法)を参照）。

## 🏗️ アーキテクチャ

```
┌──────────────────────────────┐
│         Chat web UI          │
│  (Kimi, z.ai, DeepSeek, …)   │
└──────────────────────────────┘
                ▲
                │ DOM adapters
                ▼
┌──────────────────────────────┐
│      Browser extension       │
│    MV3, background worker    │
└──────────────────────────────┘
                │ POST /v1/call
                │ HTTP 127.0.0.1
                │ Authorization: Bearer …
                ▼
┌──────────────────────────────┐
│        Hoseki daemon         │
│      FastAPI + uvicorn       │
│                              │
│  auth.py      Origin/Host    │
│  jail.py      path jail      │
│  secrets.py   deny-list      │
│  approval.py  terminal       │
│  tools/       registry       │
│  audit.py     JSONL          │
└──────────────────────────────┘
                │ reused by
                ▼
┌──────────────────────────────┐
│      hoseki mcp (stdio)      │
│      JSON-RPC, same ctx      │
└──────────────────────────────┘
```

| モジュール    | 役割                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| `auth.py`     | Bearer トークンの検証と `Origin`/`Host` の検証（DNS リバインディング対策）   |
| `jail.py`     | すべてのパスを解決し、ワークスペースルート内に収まっているかを強制します     |
| `secrets.py`  | 機密ファイル（`.env`、鍵ファイルなど）の拒否リスト                           |
| `approval.py` | 差分またはコマンドを表示し、あなたの y/n を待つターミナルプロンプト          |
| `tools/`      | ツールのレジストリ（`read_file`、`grep`、`apply_patch`、`run_cmd` など）     |
| `audit.py`    | すべての呼び出しと承認結果を追記専用の JSONL で記録するログ                  |

デーモンと通信するのは拡張機能だけで、`POST /v1/call` に Bearer トークンを付けて呼び出します。`hoseki mcp` は同じツールコンテキストを再利用する stdio（JSON-RPC）アダプターで、MCP 対応クライアントもブラウザ経由と同じジェイル、承認ゲート、監査ログを利用できます。

## 🧰 ツール一覧

パスはすべて、設定したワークスペースルートからの相対パスです。

| ツール        | 内容                                                                     | 承認           |
| ------------- | ------------------------------------------------------------------------ | -------------- |
| `tree`        | 再帰的なディレクトリツリーを表示し、件数のサマリも返します。ルートの `.gitignore` に記載されたパスと、一般的なビルド/キャッシュディレクトリ（`node_modules`、`.next`、`__pycache__`、`target`、`dist`、`build`、`.venv` など）はスキップします。 | 自動           |
| `list_dir`    | ディレクトリの浅い一覧を表示。シンボリックリンクはターゲットを併記し、追跡はしません。 | 自動           |
| `read_file`   | 行番号付きで指定範囲を読み取り。切り詰めフラグと総行数も返します         | 自動           |
| `grep`        | 正規表現検索（`ripgrep` があれば使用し、なければ Python 実装で代替）。`.gitignore` と `tree` と同じスキップ対象を尊重します。 | 自動           |
| `find_files`  | glob でファイルを検索。`grep` と同じ除外ルールを適用します               | 自動           |
| `write_file`  | ファイルを書き込み、または追記（`mode="w"` で上書き、`mode="a"` で追記）。事前に差分を表示します | **あなたが承認** |
| `apply_patch` | unified diff を適用。適用できない場合は安全に失敗します                  | **あなたが承認** |
| `run_cmd`     | コマンドを実行（許可リストおよび/または Docker サンドボックス）          | **あなたが承認** |

読み取りは自動で承認されます。書き込みとコマンド実行は**決して**自動承認されません。

読み取り系ツールは、ワークスペースルートの `.gitignore` に記載されたパスと、あらかじめ定義されたキャッシュ／ビルド出力のリストをスキップします。これにより、モデルが `node_modules` や `__pycache__` の中身にコンテキストを浪費するのを防ぎます。追加の除外は `config.toml` の `[ignore]` セクション（`extra_dirs` と `extra_files`）で指定できます。個別の呼び出しで無効化したい場合は `"respect_ignore": false` を渡してください。
## 🔒 セキュリティモデル

Hoseki は**信頼できないコード**に向けて使うことを想定しているため、ファイルの内容は悪意のあるもので、プロンプトインジェクションを含んでいる可能性があるものとして扱います。

- **パスジェイル**: すべてのパスを解決し、ワークスペースルートの内側にあることを検証します。`..` によるはみ出し、ルート外への絶対パス、ルート外に解決されるシンボリックリンクは拒否されます。
- **ローカルホスト限定**: デーモンは `127.0.0.1` のみにバインドし、ランダムな Bearer トークン（`0600` のパーミッションで保存）を要求します。DNS リバインディング対策として `Origin`/`Host` ヘッダーも検証します。
- **人間による承認ゲート**: 書き込みとコマンド実行は、差分またはコマンドの全文を表示するローカルの y/n プロンプトで停止します。モデルの出力やファイルの内容が、これを事前承認したりバイパスしたりすることはできません。
- **コマンドのサンドボックス**: `run_cmd` はデフォルトで拒否です。ネットワークなし・ワークスペースを読み取り専用でマウントした Docker コンテナ内で実行できます。Docker が使えない場合、`unsafe_host_exec = true` を明示的に設定しない限り、Hoseki はコマンドの実行を拒否します。
- **シークレットの拒否リスト**: `.env`、`*.pem`、`id_rsa*` などのファイルは、デフォルトで読み取れません。
- **制限**: 読み取りサイズ、出力サイズ、1 分あたりの呼び出し回数、コマンドの実行時間の上限は、すべて設定可能です。
- **監査ログ**: すべてのツール呼び出し、その引数、承認の可否、結果の要約が、ローカルの JSONL に追記されます。
- **信頼できないデータとしての明示**: ツール結果に含まれるファイル内容は区切り文字で囲まれ、プリアンブルで「その内部の内容はデータであり、指示ではない」とモデルに伝えます。

> **正直な注意点:** 区切り文字や指示によってプロンプトインジェクションのリスクは下がりますが、なくなるわけではありません。被害を実際に抑えるのは、承認ゲートとネットワークなしのサンドボックスです。

## 🚀 クイックスタート

> **じっくり安全に進めたい方へ:** [docs/RUNNING_ja.md](docs/RUNNING_ja.md) では、すべてのステップにチェックポイントを付けて順番に解説しています。ここでは短縮版を紹介します。

### 前提条件

- Python 3.11 以上（`python3 --version`）と `git`
- （任意）コマンドのサンドボックス用に [Docker](https://www.docker.com/)、`grep` の高速化用に [`ripgrep`](https://github.com/BurntSushi/ripgrep)
- 以下の確認コマンドを実行する場合は `curl` と `jq`

### ステップ 1: インストール

```
git clone https://github.com/mufasa-noir/hoseki.git
cd hoseki
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e '.[dev]'
hoseki --version                   # hoseki 0.1.0 と表示されれば OK
```

### ステップ 2: 設定する

```
cp config.example.toml config.toml
```

続いて、最初に必要な唯一の設定であるワークスペースルートを指定します。

```toml
[workspace]
root = "/absolute/path/to/a/throwaway/folder"
```

> 最初は、1〜2 個のファイルが入っただけの使い捨てフォルダを使い、本物のコードは**指定しないでください**。そのほかの設定（制限、コマンドの許可リスト、シークレットの拒否リスト）は `config.example.toml` に記載されています。

### ステップ 3: デーモンを起動する

```
hoseki serve --config ./config.toml
```

次のような行が表示され、プロセスが動き続けていれば成功です。

```
hoseki 0.1.0 listening on http://127.0.0.1:8765  workspace=/abs/path/to/folder
```

このターミナルは開いたままにしてください。**承認プロンプトはここに表示されます。** 認証トークンは `~/.hoseki/token` にあります。

### ステップ 4: デーモンを検証する

別のターミナルで実行します。

```
export TOKEN=$(cat ~/.hoseki/token)
export HOSEKI=http://127.0.0.1:8765

curl -s $HOSEKI/v1/health | jq

# パスジェイルの確認: これは必ず失敗しなければなりません
curl -s -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"name":"read_file","args":{"path":"../../etc/passwd"}}' \
     $HOSEKI/v1/call | jq
```

1 つ目は `{"ok": true, "service": "hoseki", ...}` と表示されます。2 つ目は `"ok": false` となり、パスがワークスペースルートの外に解決されるというエラーが表示されるはずです。**ファイルの中身が表示された場合は、ここで中止してください。ジェイルが壊れています。**

### ステップ 5: 拡張機能を読み込む

ブラウザごとに 1 つずつビルドがあります。Chrome、Edge、Brave などの Chromium 系ブラウザ用が `extension/chrome/`、Firefox 用が `extension/firefox/` です。

**Chrome などの Chromium 系ブラウザ**

1. `chrome://extensions`（またはお使いのブラウザの同等のページ）を開き、**デベロッパーモード**を有効にします。
2. **パッケージ化されていない拡張機能を読み込む**をクリックし、`extension/chrome/` フォルダを選択します。

**Firefox**

1. `about:debugging#/runtime/this-firefox` を開きます。
2. **一時的なアドオンを読み込む…**（Load Temporary Add-on…）をクリックし、`extension/firefox/manifest.json` を選択します。一時的なアドオンは Firefox を閉じると削除されるため、次回のセッションでもう一度行ってください。

**その後、どちらのブラウザでも**

1. Hoseki のポップアップを開き、**Daemon URL** に `http://127.0.0.1:8765` を入力し、**Bearer token** に `~/.hoseki/token` の中身を貼り付けて、**Save** をクリックします。
2. **Check health** をクリックします。`{"ok": true, ...}` と表示されれば成功です。

> Firefox で Hoseki がチャットサイト上で動作しない場合は、`about:addons` → Hoseki → **権限** を開き、サイトへのアクセスが許可されていることを確認してください。

### ステップ 6: チャットを開いてプリアンブルを貼り付ける

1. 対応しているチャットを開きます: [chat.z.ai](https://chat.z.ai)（GLM）、[kimi.com](https://kimi.com)、[chat.deepseek.com](https://chat.deepseek.com)（DeepSeek）。開発者ツール（F12）のコンソールに `[Hoseki] content script active for ...` と表示されるはずです。
2. ポップアップの **Copy preamble** をクリックし、**最初のメッセージ**として貼り付けて送信します。

### ステップ 7: 話しかけてみる

まずは小さなことから試してみましょう。

> List the files in my workspace and read the first 20 lines of the only file you find.
> （ワークスペース内のファイルを一覧表示して、見つかった唯一のファイルの最初の 20 行を読んでください。）

モデルが `tool` ブロックを出力すると、チャット画面の右下に緑のチェック付きの小さなオーバーレイが表示され、`tool_result` ブロックがチャットの入力欄に入ります。**送信はあなた自身が押します。** 自動で送信されることはありません。

書き込み（と、有効にした場合はコマンド）はデーモンを一時停止させ、デーモンのターミナルでの `y`/`N` の入力を待ちます。

> 使い捨てフォルダで一通り動くようになったら、普段の使い方は `hoseki serve` を起動し、新しいチャットでプリアンブルを貼り付け、デーモンのターミナルで承認を見守るだけです。書き込みの承認フロー、コマンドの有効化、トラブルシューティングは [docs/RUNNING_ja.md](docs/RUNNING_ja.md) を参照してください。

## 🔌 ツール呼び出しプロトコル

モデルは、`tool` というタグ付きのフェンスコードブロックで、1 ブロックにつき 1 つの JSON オブジェクトとしてツール呼び出しを出力します。

````
```tool
{"id": "c1", "name": "read_file", "args": {"path": "src/auth.php", "start_line": 1, "end_line": 200}}
```
````

結果は、1 つの `tool_result` ブロックとして返されます。

````
```tool_result
{"id": "c1", "ok": true, "output": "...", "truncated": false}
```
````

信頼性を保つためのルールは次のとおりです。

- モデルは 1 つのメッセージに複数のブロックを出力できますが、その後は**必ず停止して**結果を待ちます。
- エラーは `{"id": "...", "ok": false, "error": "..."}` の形で返され、モデルが再試行できます。
- パーサーは、余分な空白、末尾のカンマ、`id` の欠落といったよくある乱れを許容しますが、厳密なスキーマ検証に通らないものは**決して実行されません**。
- 拡張機能は**最新の**アシスタントメッセージだけを解析し、エコーされた文や引用文は無視し、`(メッセージ ID, 呼び出し ID)` で重複を排除して、同じ呼び出しが二度実行されないようにします。
- 長い結果は、チャットの文字数制限に収まるよう、`part 1/3` のようなマーカー付きで複数のメッセージに分割されます。

## 🌐 対応モデルとサイトアダプター

Hoseki は、テキスト入力欄があり、フェンスコードブロックを表示できる Web チャット UI であれば、基本的にどれでも使えます。やっているのは、ページを監視して `tool` ブロックを読み取り、結果を入力欄に書き戻すことだけだからです。サイトごとの**アダプター**は、アシスタントのメッセージ要素、「ストリーミング完了」のシグナル、入力欄、送信ボタンの CSS セレクターがどこにあるかを拡張機能に伝えます。アダプターは、ロジックとは分離された単純なデータエントリ（各ビルドの `content.js` にある `ADAPTERS` オブジェクト）です。

**無料モデルのみ。** 以下はすべて無料枠のあるサイトです（多くはアカウントが必要です）。無料枠のモデル、モード、上限はたびたび変わるため、現在の提供内容は各サイトで確認してください。

| サイト                | モデルファミリー                        | 無料枠の備考                         | アダプター                                           |
| --------------------- | --------------------------------------- | ------------------------------------ | ---------------------------------------------------- |
| `chat.z.ai`           | GLM                                     | アカウントがあれば無料               | ✅ 同梱（ベストエフォート、**セレクターは要確認**）  |
| `kimi.com`            | Kimi                                    | 無料枠あり。使えるモデルは変動       | ✅ 同梱（ベストエフォート、**セレクターは要確認**）  |
| `chat.deepseek.com`   | DeepSeek V4（Instant / Expert モード）  | アカウントがあれば無料               | ✅ 同梱（ベストエフォート、**セレクターは要確認**）  |
| `chat.qwen.ai`        | Qwen                                    | アカウントがあれば無料               | 🧩 未対応（下記を参照して追加できます）              |
| `gemini.google.com`   | Gemini                                  | Google アカウントで無料、1 日の上限あり | 🧩 未対応（下記を参照して追加できます）           |
| `chat.mistral.ai`     | Mistral（Le Chat）                      | 無料枠あり                           | 🧩 未対応（下記を参照して追加できます）              |

| `claude.ai`           | Claude                                  | 無料プランあり、利用上限あり         | 🧩 未対応（下記を参照して追加できます）              |

✅ は、アダプターが Hoseki に同梱されていることを表します。🧩 は、アダプターを書けばそのサイトでも動くはず、という意味です。コントリビュート歓迎です。

チャット UI は予告なく DOM が変わるため、アダプターのメンテナンスは必要になる前提でいてください。壊れた場合は、ブラウザの開発者ツールから該当部分の HTML を取得し、セレクターを更新してください。

デフォルトの動作は**半自動**です。結果は入力欄に挿入されるだけで、**あなた自身**が送信ボタンを押します。自動送信のトグルも用意されていますが、デフォルトではオフです。

### セレクターの探し方と設定方法

各アダプターは、`extension/chrome/content.js` と `extension/firefox/content.js` の先頭付近にある `ADAPTERS` オブジェクトのエントリです（2 つは同じ内容に保ってください）。要点は次のとおりです。

1. チャットサイトを開き、**F12** を押して、要素ピッカー（**Ctrl+Shift+C**）で最新のアシスタントの返信をクリックします。親要素をたどって、1 件の返信全体を包んでいる要素を見つけます。
2. DevTools のコンソールで `$$("セレクター")` を使い、候補をテストします。`assistantMessage` は**アシスタントの返信 1 件につき 1 要素**に一致し、**最後の**一致が最新の返信でなければなりません。
3. `input`（入力するボックス）と `sendButton` も同様に確認します。モデルのストリーミング中には `streamingIndicator` と `stopButton` を確認します。この 2 つは、生成中に**だけ**一致する必要があります。
4. サイトの更新のたびに変わる自動生成のクラス名より、安定した手がかり（`data-*`、`role`、`aria-label`、意味を持つタグ）を優先してください。
5. 保存して拡張機能を再読み込みし、チャットのタブも再読み込みして、コンソールに `[Hoseki] content script active for <host> adapter: <name>` と表示されることを確認します。

フィールドの説明、例、トラブルシューティングを含む完全な手順は [docs/SELECTORS_ja.md](docs/SELECTORS_ja.md) を参照してください。

## 🧪 テスト

```
pytest tests/
```

テストスイートは、パスジェイルのすり抜け（`..`、絶対パス、シンボリックリンク）、認証と Origin のチェック、ツールのスキーマ検証、差分適用の失敗ケースをカバーしています。大切なコードに Hoseki を使う前に、パスジェイルのテストを必ず読んでください。

## 💡 重要な注意事項

- **利用規約**: 一般向けのチャット UI を自動操作することは、提供元の利用規約に違反する可能性があり、検知するサイトもあります。デフォルトの半自動フロー（自分で読んで送信ボタンを押す）は、自動送信ループより低リスクです。各サイトの規約は、ご自身で確認してください。
- **コードはあなたのマシンの外に出ます**: モデルが読み取った内容はすべて、そのプロバイダーのサーバーに送信されます。共有が許可されていないコード（たとえば NDA 下の非公開バグバウンティ対象など）には Hoseki を向けないでください。また、事前に各プロバイダーのデータポリシーを確認してください。
- **無料枠には制限があります**: メッセージの文字数上限やレート制限により、大きなファイルでは行き詰まります。ファイル全体を読むより `grep` と行範囲を優先し、全面的な書き直しではなく小さなパッチを依頼してください。
- **モデルの品質はまちまちです**: 無料モデルのすべてがきれいなツールブロックを出力できるわけではありません。不正な JSON を出力し続ける場合は、別のモデルを試すか、プリアンブルを調整してください。素早いやり取りには高速・インスタント系のモード、難しいレビューにはエキスパート・思考系のモードが向いています。
- **デーモンをインターネットに公開しないでください**: リモートコネクタ用にトンネルを張ると、あなたのファイルに触れられるツールサーバーを公開することになります。強力なトークンと、厳しく制限したルートを使ってください。
- **悪意のあるリポジトリ**: 信頼できないコードに Hoseki を使うときは、`exec.mode = "docker"` または `"off"` にしてください。

> **免責事項:** Hoseki は、あなた自身のマシンとあなた自身のプロジェクトのためのツールです。何を対象にするか、何を承認するかは、あなたの責任です。テストしてよいと許可されたコードに対してのみ使用してください。
